# ADR-010 — Imagens em disco atrás de interface de armazenamento

Status: proposta (arquiteto: Eric) · Baseline: 2026-11-03.1 · Requisitos: RF-06, RF-19

## Contexto
RF-06: PNG, JPG ou WebP de até 5 MB, para fundo ou objeto; fora disso é recusado e nada é gravado. A stack prevê disco no MVP e S3 compatível depois.

## Decisão
- Interface `Armazenamento { gravar, ler, apagar }` com implementação em disco no MVP; trocar por S3 não muda as rotas.
- Em `POST /assets`, o Fastify limita o corpo a 5 MB (rejeita antes de gravar); o limite de 50 MB de `POST /fases/importar` (ADR-013) vale só para o envelope, e cada imagem embutida continua limitada a 5 MB. O tipo é conferido pelos bytes iniciais (assinatura do arquivo), não pela extensão.
- Toda referência `asset:<uuid>` num documento salvo, publicado ou importado precisa existir e pertencer ao dono da fase; senão a Api recusa com 400. Assim uma fase nunca depende de imagem de outra conta (RF-19).
- O registro em `assets` e o arquivo são gravados juntos; falha em um desfaz o outro.

## Consequências
- Imagens enviadas por um criador são públicas por URL quando usadas em fase publicada.

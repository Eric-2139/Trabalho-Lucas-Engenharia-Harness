# ADR-002 — PostgreSQL com a fase em JSONB, rascunho e versão publicada

Status: proposta (arquiteto: Eric) · Baseline: 2026-11-03.1 · Requisitos: RF-02, RF-10, RF-13

## Contexto
Usuários e metadados são relacionais (dono, publicação, datas); a fase é um documento que muda de forma junto com o schema. O salvamento automático (RF-10) grava a cada 30 s. A PEND-005 decidiu: editar uma fase publicada não muda o que os jogadores veem até o criador publicar de novo.

## Decisão
- Tabela `fases` com metadados relacionais e o documento em `documento jsonb`.
- Ao publicar, a API copia o documento validado para `documento_publicado` e grava `publicada_em`. O jogo e `/publicadas` leem só `documento_publicado`.
- Salvar é `PUT /fases/:id` com o documento completo e a `revisao` atual; revisão diferente devolve 409 (duas abas abertas não se sobrescrevem em silêncio).
- Excluir é físico (`DELETE`), sem lixeira: RF-02 diz que Ctrl+Z não restaura fase excluída.
- Título: a fonte da verdade é `documento.titulo`. A coluna `fases.titulo` é cópia que a Api atualiza a cada gravação, só para "Minhas fases". Escolher Fase mostra `documento_publicado.titulo`, o título da versão que o jogo usa. Renomear é `PATCH /fases/:id { titulo }`, que altera o documento e a coluna e incrementa `revisao` (operação de servidor, fora do histórico: ADR-008).

## Consequências
- Confirmado pela PEND-005: o salvamento automático só altera `documento`; `documento_publicado` muda apenas em `publicar`. `GET /fases/:id` devolve `alteracoesNaoPublicadas` (a Api compara os dois documentos), que o editor usa para mostrar o aviso e o botão "publicar de novo". Exportar e duplicar usam sempre `documento` (a versão em edição do autor).
- Consultas dentro do documento (ex.: buscar por objeto) não são previstas no MVP; não há índice GIN.
